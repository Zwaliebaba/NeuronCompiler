# 16 — Open questions

Decisions this draft does not make. Each has a recommendation, so silence is a default, but the ones marked **needs you** are ones I think you should actively decide because they depend on intent rather than engineering.

| ID | Question | Recommendation | Raised in |
|----|----------|----------------|-----------|
| Q-01 | **Needs you.** Licence for NeuronCompiler, and separately for `libncrt` and the headers, which get linked into or included by user programs. | Apache-2.0 with LLVM-style runtime exception, or MIT for everything. A copyleft licence on `libncrt` would make the compiler unusable for most Windows software. | — |
| Q-02 | **Needs you.** How do we work: who implements which parts, in what cadence, and how much is generated by me versus written or reviewed by you? This decides whether phases 3 and 4 run in parallel. | Treat each document as a component spec; implement phase 0 first as a vertical slice and revisit the roadmap with real velocity data. | [15](15-roadmap.md) |
| Q-03 | **Needs you.** Is the C23 `printf`/`scanf` implementation in `libncrt` the default under `/std:c23`? | Yes. Otherwise the "full C23" claim is false in a way users can observe with one `printf("%b")`. Provide `/Qucrt-stdio` to opt out. | [01](01-goals-scope-risks.md), [11](11-runtime-and-headers.md) |
| Q-04 | Decimal floating point after v1, or never? | Defer the decision until v1 ships; nobody on Windows is asking for it. | [01](01-goals-scope-risks.md) |
| Q-05 | `BITINT_MAXWIDTH`: 65535 or Clang's 8388608? | 65535 for v1. Raising it later changes no ABI and only stresses compile-time bigint performance. | [01](01-goals-scope-risks.md) |
| Q-06 | Raise the default target baseline from ARMv8.0 to ARMv8.1 (LSE atomics)? | Keep v8.0 as the default until the supported Windows 11 hardware baseline is confirmed to require LSE; then switch, since LL/SC loops are measurably slower under contention. | [01](01-goals-scope-risks.md), [06](06-arm64-backend.md) |
| Q-07 | Is kernel-mode (driver) code generation a future goal? | Not in v1, but keep the design compatible (it already is: no red-zone use, `x18` untouched, stack probing). | [01](01-goals-scope-risks.md) |
| Q-08 | Accept UTF-16 source files? | Yes, transcode on load when a BOM is present; it is cheap. | [03](03-frontend.md) |
| Q-09 | `/Qcommon` default? | Off (ISO semantics), matching modern GCC/Clang. Revisit if real-world corpus builds fail because of it. | [03](03-frontend.md) |
| Q-10 | Accept empty structs at all? | Only under an explicit GNU-extension switch. | [04](04-msvc-compatibility.md) |
| Q-11 | Ship ACLE `<arm_neon.h>` in addition to MSVC's `arm64_neon.h` intrinsics? | Yes, post-v1: portable NEON code (e.g. from Linux/Android libraries) uses ACLE names. | [04](04-msvc-compatibility.md) |
| Q-12 | Implement `__ptr32`? | Parse it, implement only if an SDK header used in practice needs it. | [04](04-msvc-compatibility.md) |
| Q-13 | Strict aliasing on by default for new code (`/std:c23 /permissive-`)? | No. A default that depends on another flag is a trap; keep it opt-in everywhere. | [05](05-ir-and-optimizer.md) |
| Q-14 | Function argument evaluation order. | Left-to-right, documented. The order is unspecified in C; matching MSVC's order buys nothing. | [05](05-ir-and-optimizer.md) |
| Q-15 | Pre-RA instruction scheduler? | Not in v1. Measure on Oryon/Cortex-X class cores first; wide out-of-order cores are forgiving. | [06](06-arm64-backend.md) |
| Q-16 | Function fragments (functions > 1 MiB, shrink-wrapping) in v1? | No; diagnose oversized functions. | [06](06-arm64-backend.md) |
| Q-17 | Skip callee re-extension of narrow arguments for internal-linkage callees? | Yes at `-O2`, as an IPO-lite optimisation where both sides are ours. | [07](07-windows-arm64-abi.md) |
| Q-18 | `/Gw` (per-object data COMDATs) default at all levels? | Yes; the cost is section count, which bigobj handles. | [08](08-coff-object-writer.md) |
| Q-19 | Exact SEH funclet / establisher-frame convention on ARM64. | Determine empirically from `cl` output before phase 6; do not guess. | [09](09-unwind-and-seh.md) |
| Q-20 | **Needs you.** SEH in v1.0, or v1.1? | v1.0. Win32 code uses `__try` more than people expect, and its absence makes `ncc` unusable for exactly the code that needs `windows.h`. | [09](09-unwind-and-seh.md) |
| Q-21 | Debugger display of `_BitInt(N > 64)`. | Ship a natvis file; CodeView has no native representation. | [10](10-codeview.md) |
| Q-22 | Variadic `assert` overlay unconditional? | Yes; it is a strict superset of the UCRT behaviour. | [11](11-runtime-and-headers.md) |
| Q-23 | Math algorithm sources for the C23 `<math.h>` additions. | CORE-MATH (correctly rounded, MIT) where available, musl (MIT) otherwise. | [11](11-runtime-and-headers.md) |
| Q-24 | Upstream CMake support for `ncc` as a distinct compiler id. | Use the documented toolchain file until v1; propose upstream after. | [12](12-driver-and-toolchain.md) |
| Q-25 | **Needs you.** Buy a commercial conformance suite before claiming C23 conformance publicly? | Yes, if the compiler is meant for anyone but us. Without one, the claim rests on tests we wrote ourselves. | [14](14-testing-strategy.md) |
